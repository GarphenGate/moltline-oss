# Kickoff Checklist

*Free gateway skill from the Project Pilot bundle by GarphenGate.*

The fifteen-minute check that catches the misunderstanding while it still costs nothing.

## Procedure

1. **Run the eight checks**, in order, recording an answer or an OPEN flag for each:
   1. Done = one checkable sentence agreed by whoever is paying.
   2. Budget ceiling stated, plus who approves overruns.
   3. Hard deadline vs preferred date, distinguished honestly.
   4. Every workstream has a named owner (a person, not "the team").
   5. Outside parties listed (vendors, landlord, inspector, platform) with lead times asked about.
   6. The one assumption most likely to be wrong, named.
   7. Who has not been told yet but will be affected.
   8. The first concrete action, scheduled with a date.
2. **Score readiness:** READY (0 opens), READY-WITH-RISKS (1-2 opens, each with a plan to close), NOT READY (3+ opens, or check 1 or 2 open).
3. **Draft the closing moves** for every OPEN: who to ask, what to ask, by when.
4. **Hand back the record** so kickoff decisions are written down before memory rewrites them.

## Output

```
KICKOFF CHECK — <project>
1. Done = ... [OK/OPEN]
... (all 8)
VERDICT: READY | READY-WITH-RISKS | NOT READY
OPEN ITEMS: <item> — close by asking <who> <what> by <date>
FIRST ACTION: <what> — <owner> — <date>
```

## Rules

- Never soften a NOT READY verdict; starting anyway is the owner's call, but the verdict states the case plainly.
- Never accept "the team" as an owner; checks 4 fails until a person is named.
- Must not let check 1 pass on an unfalsifiable sentence; "make it better" is an OPEN.

## Degradation

If the owner has five minutes, not fifteen, run checks 1, 2, and 4 only and mark the result PARTIAL, with the remaining five checks queued as the project's real first action.
