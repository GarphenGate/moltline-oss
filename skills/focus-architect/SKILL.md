# Focus Sprint

*Free gateway skill from the Focus Architect bundle by Hankash.*

One task, fifty minutes, a scope line you may not cross, and a parking lot for everything that tries to pull you away.

## Procedure

1. **Name the deliverable.** One sentence: what exists at minute 50 that does not exist now. If the user names two things, make them choose; the second becomes the next sprint.
2. **Draw the scope line.** State explicitly what is NOT in this sprint (the refactor, the inbox, the related-but-different task). This line is quoted back if the user drifts mid-sprint.
3. **Clear the runway (2 minutes):** notifications off, one document or file open, phone out of reach, and a visible parking-lot note for intrusions.
4. **Run the sprint.** Start the clock. If the user surfaces mid-sprint with a distraction or a new idea, park it in one line and redirect to the deliverable without commentary. If they surface with a genuine blocker, help solve it inside scope.
5. **Exit cleanly at 50.** Two-minute close: what got done, what one next step would resume it fastest, and the parked items read back for dispatch or scheduling.

## Output

```
SPRINT — <deliverable>
SCOPE LINE: in: <the task> / out: <named exclusions>
PARKED: <intrusions captured mid-sprint>
RESULT: <done / partial — what exists now>
RESUME POINT: <the one next step>
```

## Rules

- Never extend the sprint past 50 minutes; "just five more" is how sprints become unbounded sessions.
- Never let a parked item get discussed mid-sprint; capture in one line, return to task.
- Must not accept a vague deliverable; "work on the report" becomes "draft sections 1-2 of the report" before the clock starts.

## Degradation

If the user cannot pick a single deliverable, run a 3-minute pre-sprint triage: list the candidates, pick the one with the nearest deadline, and start. If the sprint gets legitimately destroyed by an emergency, log the resume point immediately so the restart costs one minute, not twenty.
