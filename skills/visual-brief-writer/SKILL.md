# Brief Template

*Free gateway skill from the Visual Brief Writer bundle by GarphenGate.*

The one-page brief skeleton, pre-filled with whatever the user already knows and honest about what they don't.

## Procedure

1. **Take the project description** in whatever shape it arrives: a sentence, a client email, a ramble.
2. **Fill the template sections** (audience, action, message, deliverables, constraints, success criteria, anti-goal, references) from the description, using only what it actually supports.
3. **Mark every empty or guessed section OPEN**, each with the single question that would fill it, phrased so the user can forward it to a client verbatim.
4. **Draft one placeholder success criterion and one anti-goal** even from thin input, labeled DRAFT, so the user sees the standard the section is meant to reach.
5. **Deliver template plus a fill order**: which OPEN questions to answer first because other sections depend on them.

## Output

```
BRIEF (v0): <project>
AUDIENCE: <filled | OPEN — ask: ...>
ACTION: <filled | OPEN — ask: ...>
MESSAGE: <filled | OPEN — ask: ...>
DELIVERABLES: <filled | OPEN — ask: ...>
CONSTRAINTS: <filled | OPEN — ask: ...>
SUCCESS CRITERIA: <filled | DRAFT: ...>
ANTI-GOAL: <filled | DRAFT: ...>
REFERENCES: <filled | OPEN>
FILL ORDER: 1. <question> 2. <question> 3. <question>
```

## Rules

- Never fill a section by inventing facts the description doesn't support; an honest OPEN beats a confident guess.
- Never deliver the template without the fill order; a form with eight blanks and no priority is homework, not help.
- The whole brief stays on one page, including the OPEN markers.

## Degradation

Given nothing but a project name, deliver the empty template with all sections OPEN and the fill order as a five-minute client interview script.
